# PrivacyScreen 手动验证与回归清单

**适用：v1.4 / Windows 10 2004+、Windows 11 / .NET 8 / x64。**

本仓库的 GitHub Actions 负责构建，不包含 Windows GUI、音频端点或网易 UU 的自动化实机验收。建议每次升级前备份 `%LOCALAPPDATA%\PrivacyScreen\config.json`，并确认有通过 `Ctrl+Alt+Del` 注销或重新启动的应急途径。

## 1. 构建与首次运行

- [ ] 在 `PrivacyScreen.WinForms` 目录运行 `dotnet restore` 和 README 的 `dotnet publish`，生成一个可运行的 `publish\PrivacyScreen.exe`。
- [ ] 首次启动显示设置页，设置的密码能写入用户配置（仅盐/哈希，不含明文）。
- [ ] 托盘常驻；默认 `Ctrl+Alt+S` 启动隐私屏保，`Ctrl+Alt+U` 出现绘制密码框；输入正确密码后解锁。
- [ ] 原 v1.2.1 `config.json` 在新版本能无重设密码地打开；保存设置后新字段出现，密码 Salt/Hash/Iterations 未变化。

## 2. 屏保原有能力（不得退化）

- [ ] 多显示器分别全屏遮挡，无时钟日期；本地实体键鼠、Alt+Tab、Win 键和 Alt+F4 不能切走屏保。
- [ ] 无图片时出现渐变+自定义文字；导入图片时按顺序轮播，坏图跳过、清空后渐变恢复。
- [ ] 本地解锁密码验证与错误提示有效；通过密码解锁前，远程输入不能关闭屏保。
- [ ] 与网易 UU 远程配合：远程看到真实桌面，能点击/输入；本地继续显示屏保。**需单独实测，不能由 API 调用成功推断。**
- [ ] 锁定失败/回滚没有残留屏保、指示图或输入钩子。

## 3. 狗头状态指示

- [ ] 默认主屏右上角狗头紧贴顶部，向右越界约 28%，透明轮廓自然；左上角模式翻转且相同程度越界。
- [ ] 远程桌面捕获能看到狗头；远程操作可以点击穿透狗头位置。
- [ ] 只有锁定成功后显示；解锁或失败回滚立即消失。
- [ ] 关闭开关后不显示；更换自定义图与恢复默认图生效；日志含 `Indicator:` 状态、来源及 bounds。

## 4. 内置扬声器：专项测试

请**先播放不涉及隐私的短提示音**，观察 Windows 声音设置中的端点状态。若机器上有外接设备，分别测试 USB 声卡、蓝牙耳机、HDMI/DP 显示器输出。

- [ ] 托盘常驻但未锁定时，本机内置扬声器不受影响。
- [ ] 「锁定时静音内置扬声器」默认勾选。成功锁定后，内置扬声器 Mute=true；音量数值完全不变。
- [ ] 原本 Mute=false 的端点：解锁恢复为 false；原本 Mute=true 的端点：解锁仍为 true。
- [ ] 外接 USB、蓝牙、HDMI/DP 输出在识别正常的情况下没有被静音。检查 `app.log` 的候选名称、FormFactor、连接类型和分类依据。
- [ ] 修改静音开关为关闭后，锁定/解锁不主动触碰音频端点。
- [ ] 关闭音频服务、无法访问设备或找不到匹配端点时，`Audio:` 记录错误但屏保仍成功锁定和解锁。
- [ ] 在已静音期间**强制结束程序**（事先保存所有工作），确认 Windows 输入钩子撤销，`audio-restore.json` 留存；重新启动 EXE 时自动恢复原 Mute 并移除成功完成的记录。
- [ ] 在强杀后保持音频设备断开再启动：恢复失败的条目保留；重新插上设备后使用托盘「恢复扬声器」尝试完成恢复。
- [ ] 启动恢复适用于当前配置关闭静音开关的情形（恢复以前的崩溃状态属例外）。
- [ ] 比较网易 UU 远程端是否仍能听到 WASAPI loopback 音频；**此项结果依赖 UU 实际采集路径，可能成功也可能失效**。

## 5. 无边框全屏 Z 序保护（v1.4）

- [ ] 从 v1.3.2 的 `config.json` 直接升级：无需重新输入密码，保存设置后新增 `FullscreenGuardEnabled: true`；关闭开关后不会启动看门狗。
- [ ] 锁定成功日志出现 `Guard: started mode=WinEvent+timer`、`hooks=3/3`（如果事件注册失败，必须记录错误且仍有定时器兜底）。
- [ ] **锁定之后**启动常规 Unity FullScreenWindow/其他无边框置顶全屏游戏：本地屏保重新覆盖、远程仍能正常操作游戏，游戏焦点保持不变。
- [ ] 另用自制置顶全屏测试窗验证：即使新窗口位于任一盾窗上方，日志 `Guard: reasserted` 包含其进程名、标题和真实重叠尺寸；隔 2 秒内不会连续刷同类重申日志。
- [ ] 多显示器分别启动越界/重叠窗口，任一盾窗被遮挡都会按顺序重新置顶全部盾窗、最后狗头。
- [ ] 1×1 壳窗口、最小化、不可见、DWM Cloaked 或完全位于其他显示器且无实际交集的窗口不触发置顶。
- [ ] 锁定时按本地 Ctrl+Alt+U 输入密码：密码卡片仍位于盾窗之内，没有被看门狗盖住；解锁开始时立即停止 Guard。
- [ ] 使用 Windows 安全屏幕/任务管理器尝试应急恢复：`Guard: emergency window respected`，不要与 Taskmgr / Process Explorer 等不断争抢层级。
- [ ] 如果游戏是真正独占全屏，记录无法保证覆盖这一局限，不要强制修改游戏显示设置。
- [ ] 关闭、解锁、锁定失败、重复开启等生命周期路径没有残留 WinEvent hook、定时器或狗头。

## 6. 应急处理与收集日志

- 若无法正常解锁，可通过 `Ctrl+Alt+Del` 进入 Windows 安全界面后注销/重启或使用任务管理器结束程序。它不是不可绕过的安全锁。
- 如果被动静音没有恢复：关闭屏保后打开托盘「恢复扬声器」；仍无法恢复时重启程序、检查设备是否重新连接。日志位置：`%LOCALAPPDATA%\PrivacyScreen\app.log`。
- **不要**向公共 Issue 上传密码哈希/盐、包含真实姓名或路径的配置、未处理的音频端点 ID、应用日志全量或个人照片。日志提交前请脱敏。
